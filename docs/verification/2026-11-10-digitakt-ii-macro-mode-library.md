# Digitakt II: Macro Mode 0.1.0-experimental for the library — 10 November 2026

toonst's macro mode (toonst/digi_macro `62f0b0a`, the build it makes with `MM_KITS=project`) is prepared as the Digitakt II's first module on Modwerk's base: hold PAGE and press MOD, and encoders A–H become eight macros, each moving up to four parameters on chosen tracks on top of the sound, with one setup per project. Its source-only OS 1.17 package is pinned in `sdk/imports/elekloader-macro-mode-2026-11-10.json` (commit `1c3f1e8e`).

- **Build:** `scripts/build-elemod-packages.mjs` with m68k-elf GCC 16.2.0 and binutils 2.47 built from GNU's release archives (the versions and checksums of `sdk/build/Dockerfile`), the toolchain that reproduces the base's recorded identity. Two builds give the same recipe, and `package-elemod-recipe.mjs --check` matches the committed package. Not yet built in `modwerk-source-tools`; CI's elemod-source job does that.
- **Package:** `macro-mode-0.1.0-experimental-os1.17.elemod` `5791a094…7c25`, 19,793 bytes of `.run`, 8,275 of `.bss`, no sites. It imports `core_kit_on` and `core_store_conflicts`, subscribes to `ev_key`, `ev_enc`, `ev_tick`, `ev_draw`, `ev_frame_params` and `ev_key_leds`, and contributes one record to `core_projdata`.
- **Image:** the site's builder path (`prepareBuild`, `buildWithLock`, the vendored kit 0.7.0) links the base and the package on the contributor's stock `Digitakt_II_OS1.17.syx` (`26c22f66…`), alone (`6be06fd9…`) and with Perform Direct and Perform Levels (`5f2ae3ba…`). Both pass `preflightBuiltFile` and elekloader's verify, and elekloader's own linker gives the same main OS as the first.
- **Emulator:** digikit's `zero_patched` runner (digikit `3d3a243`) with digi_macro's scenarios at `8b67398`, on the first image: `project_only.py` 23 of 23, `compat_project.py` 13 of 13, and 91 of `scenario.py`'s 94, whose three restart checks look for a card record this build does not keep. A new project (CREATE NEW) starts with a copy of the setup that was on. The image with the perform mods boots to the main screen and shows the same macro page. [TESTING.md](../../sdk/digitakt-ii/modules/macro-mode/TESTING.md) has what each covers.
- **Load:** counted in the emulator, not timed: the module's hook in the frame interrupt runs 4 instructions with no macro set up, 1,831 with one macro on four destinations and sixteen tracks, and 12,631 with all eight, where the stock interrupt runs 44,355.
- **On a unit:** not run. The evidence tier is `emulator`, so `modules:check --base` refuses the version at the publication gate until its author has run this build on a Digitakt II and recorded it.
- **The machine's status:** a module in `sdk/digitakt-ii/modules/` is listed in the library, and four tests held the Digitakt II as a research machine with none (`src/devices/library-parity.test.ts`, `src/devices/registry.test.ts`, `src/community/module-changelogs.test.ts`). As `docs/ADD_A_MACHINE.md` has it for a machine's first module, the profile moves to preview with every step done and the machine leaves the core build preview list, as the Rytm did; those tests now describe the library. Downloads stay off (`DIGI_DOWNLOADS_ENABLED`). The promotion is its own commit (`059e3a9a`), for the owner to take or leave.
- **Why per project only:** digi_macro's own build can keep a setup per kit, which takes all 191 bytes of kit data a Digitakt II kit record has. The library's build keeps the setup in the project header's gap alone (192 of 484 bytes), so kit data stays free for other modules.
