# Digitakt II: the site builds on the Modwerk base — 10 November 2026

The configuration page builds every Digitakt II set on Modwerk's base (`sdk/machines/digitakt-ii/base-binding.json`, identity `ce3e5488…8e8f`) in place of toonst's core 1.0 record, and the machine's core version is 1.1. The base's recipe, sources and binding are unchanged: this publishes the package the binding names and points the builder at it.

- **Package:** `npm run machine:base -- digitakt-ii --stock … --out …` with m68k-elf GCC 16.2.0 and binutils 2.47 built from GNU's release archives (the versions and checksums of `sdk/build/Dockerfile`), the kit-pinned Elekloader `3b31ef3` and the contributor's own `Digitakt_II_OS1.17.syx` (`26c22f66…`) answers "Matches sdk/machines/digitakt-ii/base-binding.json": `.boot` 50, `.run` 7,327, `.bss` 3,576 bytes, 19 sites. That file is `sdk/imports/packages/modwerk-base-digitakt-ii/modwerk-base-digitakt-ii-ce3e5488.elemod` (commit `68a9b06c`), pinned in `sdk/imports/elekloader-modwerk-base-digitakt-ii-2026-11-10.json`; `npm run elekloader:check` passes with it in the catalogue.
- **Plan:** `planBuild('digitakt-ii', '1.17', …)` takes the base by its identity for an empty set and for the perform mods, and not another core of the device (`src/engine/elekloader/digi-build.test.ts`).
- **Builds:** with the stock OS, the site's builder path (`prepareBuild`, `buildWithLock`, the vendored kit 0.7.0) built the base alone, with Perform Direct, with Perform Levels and with both. Each build passed `preflightBuiltFile` (`digi-preflight.ts`: every section but the main OS stock, every changed byte inside a declared site, nothing more appended) and elekloader's `syx.verify` (the seal, the stock bootloader, the main image).
- **Emulator:** in digikit's `zero_patched` runner (toonst/digikit `3d3a243`; the runner is in that fork, not in upstream digikit) the base alone and the base with both perform mods cold-boot to a main screen identical to the stock OS's, and PLAY runs. The sequencer hooks' own results are in the [base's notes](../../sdk/machines/digitakt-ii/elekloader/modwerk/README.md).
- **module:doctor:** `scripts/module-doctor.mjs` listed the Digitakt, Digitone, Rytm and Analog Four folders and answered "No module named" for one in `sdk/digitakt-ii/modules/`. With the Digitakt II in its list it checks such a module like the others (run on a local module folder: manifest, category guide, catalogue pin, module rules).
- **On a unit:** not run for this record. Core-dt2 1.1 alone (elekloader's build of a later commit of the same source) has run on a Digitakt II with a mod on its frame values, LEDs and project and kit data, as toonst reported on 5 November.
- **Not here:** the core source stays `3d7c2e3`; taking it again once elekloader merges its core-dt2 1.1 gives a new identity. The base's `ev_seq_*` collections are not in `core-profile/interface.json` yet, so `modules:check` refuses a module that subscribes to them until they are added. Downloads stay off.
